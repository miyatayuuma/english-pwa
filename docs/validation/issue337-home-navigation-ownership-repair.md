## DOM ownership and navigation hierarchy

`#focusHomeNav` now has one renderer and action registry in `scripts/app/homeNavigation.js`. `sessionShell.js` creates the empty container and initializes the renderer. Relationship Mode, Learning Menu, and Vocabulary Mode register behavior or expose readiness/status; they do not append, remove, or reorder navigation children. The old `friendship-nav`, `learning-nav`, and `has-vocab-mode` grid-state classes are removed by the owner, and the owner applies one fixed two-column layout.

The initial lobby has three actions total:

1. Character hero: `○○に会いに行く`
2. `連絡先`
3. `遊び方を選ぶ`

Secondary routes preserve existing functions:

- `遊び方を選ぶ` → `単語チャレンジ` → `単語チャレンジを開く`
- `遊び方を選ぶ` → `詳細な条件を設定` → existing `__OPEN_SESSION_OPTIONS__` sheet
- `遊び方を選ぶ` → `範囲から` → existing range browser
- `遊び方を選ぶ` → `連絡先・トレーニング` → existing character/training browser
- `みんなと遊ぶ` is shown in the secondary menu only when the existing all-friends condition is true.

Vocabulary loading publishes `loading`, `ready`, `empty`, or `error`. The secondary start action remains disabled with a status message until the existing vocabulary data is ready; failure and empty data do not remove the home actions. Vocabulary selection, dialog, scoring, SRS, progress migration, and entry data are otherwise unchanged.
