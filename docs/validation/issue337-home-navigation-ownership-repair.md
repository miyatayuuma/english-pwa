## Status

Implementation and local non-browser regression checks are prepared on the repair branch. Production closure remains gated on required Chromium, Android, and Pages checks, merge, and post-merge verification.

- Initial `main`: `6cc3561c0518d40b82af3ed91b705d02524f16cf`

- Finding: `relationshipMode.js` cleared and rebuilt `#focusHomeNav`; `learningMenu.js` appended a learning button and used a `MutationObserver` to restore it; `vocabularyMode.js` appended a vocabulary button once during asynchronous startup. Final actions and grid styling therefore depended on module/load order.

The pre-fix comparison images are [home-360.png](../issue210-evidence/home-360.png), [home-390.png](../issue210-evidence/home-390.png), and [home-430.png](../issue210-evidence/home-430.png). At 390px, the home showed the hero start action plus three navigation actions: `遊び方を選ぶ`, `連絡先`, and `遊び方を変える`. This exposed a fourth initial action and left `遊び方を変える` competing with the learning route.

## DOM ownership and navigation hierarchy

`#focusHomeNav` now has one renderer and action registry in `scripts/app/homeNavigation.js`. `sessionShell.js` creates the empty container and initializes the renderer. Relationship Mode, Learning Menu, and Vocabulary Mode register behavior or expose readiness/status; they do not append, remove, or reorder navigation children. The old `friendship-nav`, `learning-nav`, and `has-vocab-mode` grid-state classes are removed by the owner, and the owner applies one fixed two-column layout.

The initial lobby has three actions total:

1. Character hero: `○○に会いに行く`
2. `連絡先`
3. `遊び方を選ぶ`

Secondary routes preserve existing functions:

- `遊び方を選ぶ` → `単語チャレンジ` → `単語チャレンジを開く`
- `遊び方を選ぶ` → `詳細な条件を設定` → existing `__OPEN_SESSION_OPTIONS__` sheet
- `遊び方を選ぶ` → `範囲から` → existing range browser
- `遊び方を選ぶ` → `連絡先・トレーニング` → existing character/training browser
- `みんなと遊ぶ` is shown in the secondary menu only when the existing all-friends condition is true.

Vocabulary loading publishes `loading`, `ready`, `empty`, or `error`. The secondary start action remains disabled with a status message until the existing vocabulary data is ready; failure and empty data do not remove the home actions. Vocabulary selection, dialog, scoring, SRS, progress migration, and entry data are otherwise unchanged.

## Deterministic regression coverage

`tests/homeNavigationOwnership.test.mjs` adds browser coverage for:

- All six release orders for Relationship Mode, Learning Menu, and Vocabulary Mode, with network gates rather than fixed startup sleeps.
- Same final button IDs/order, enabled state, grid, hero presence, text fit, overflow, and no duplicate actions.
- Repeated owner rendering and registration, class cleanup, one activation per tap, secondary `みんなと遊ぶ`, refresh, alternate-character start, and home return.
- Functional contact browser, Vocabulary dialog, session options fields (character, skill, section, count, selection mode), range selection, and contact/training selection.
- Delayed Vocabulary readiness, Vocabulary fetch failure, empty Vocabulary, failed character data, and protected local state across navigation-only dialog use.
- 360×844, 390×844, and 430×844 mobile viewports with dark color scheme and reduced motion.

`tests/friendshipUiModules.test.mjs` also guards the single-owner source contract and the removal of the competing mutations/observer. The test job sets `HOME_NAV_REQUIRE_BROWSER=1`, so missing Chromium fails CI instead of being accepted as a successful skip. `HOME_NAV_CAPTURE=1` captures viewport evidence under `docs/validation/issue337-evidence/` and uploads it as `issue337-home-navigation-evidence`.

Local `npm test -- --test-reporter=dot`: 609 tests, 518 passed, 0 failed, 91 skipped because this environment has no Chromium binary. This is not mobile acceptance; CI browser results and screenshots remain required before merge.
