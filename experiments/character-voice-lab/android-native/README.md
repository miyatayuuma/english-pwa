# Kokoro Pixel Lab · P3.7

Pixel 9向けの独立したARM64試験アプリ。パッケージ名は `jp.miyatayuuma.kokorop37`。研究ブランチの基準はP3.6 `1d3b06c830073315bbe51b78155c376aa23feeac`。

## Pixel 9で試す

1. このDraft PRの「Kokoro P3.7 Pixel APK」の成功した実行から `kokoro-p37-pixel-apk` を取り出す。ZIPを展開し、`Kokoro-Pixel-Lab-P37.apk` をPixelに移してインストールする。PCからは `adb install -r Kokoro-Pixel-Lab-P37.apk` でもよい。
2. 端末のスピーカーを使用。アプリを開き、Wi‑Fiで「モデルを準備」。最初は q8・CPU・4スレッド。FP32とq8の両方で約400 MBの空き容量を見込む。ダウンロードした音源・モデルはアプリ専用領域に保存され、以後も再利用される。
3. 「短文 × 5」を実行する。ウォームアップ1回に続き、同じ短文を5回計測する。「通常会話と長文」でP3.6の模擬ストリームと長文を試す。「モデル・スレッド一括比較」はq8・FP32のCPU 1/2/4/8、FP32のXNNPACK 4を計測する。
4. 有望な設定を選び、「10分連続会話」を実行。画面を前面に保ち、基準の比較では充電を外し、開始時の端末温度や室温をメモする。強い熱制限に達した場合は、その時点の結果を保存する。
5. ASRは先にマイクを許可する。ASR用の試験音声が流れている途中で「割り込んで話す」を押す。「話してください」を待ち、1回目は無言、2回目は `Please turn on the light.` と話す。スピーカー停止、無言時の誤認識、最終認識後の応答再生を確認する。各ケースを数回繰り返す。端末内英語認識が利用できない場合はAndroidの英語音声認識データを準備して再試行する。
6. 「音質比較 A → B → C」で AはP3.5事前生成、Bは選択中の端末設定、CはAと同じ音素列を使った端末生成を聞く。Jennifer・Bob（米音）とTed（英音）で話者・抑揚・発音を比較する。Jenniferでは `read` と `read-curated` も比較する。q8/FP32で同一キャラを聞き、明瞭度・歪み・同じ話者として聞こえるかを確認する。全20人の通常文を選択できる。
7. 「結果JSONを保存」でDownloadsなどに出力する。JSONには機種・OS・モデル・試験文・設定・測定値が含まれる。録音、ASRの認識文、アカウント、学習データは保存しない。

## 測定と判定

| 項目 | 測定値 |
|---|---|
| モデル準備 | 検証・ダウンロード、ORTセッション生成、音素化器／トークナイザ準備、声ベクトル読み込みを別に記録 |
| 発話 | 音素化とトークン化、ORT入力準備と推論、出力読み出しとPCM変換を別に記録 |
| 再生開始 | 音声要求から AudioTrack の再生ヘッドが進んだことの初回観測まで。発音のある10 ms窓の到達は別列。ハードウェアタイムスタンプが取れた場合は補助推定を記録 |
| RTF | 音素化＋ORT＋PCMの秒数を再生対象PCM秒数で除算。トリム前後の長さも保持 |
| 会話 | 文・句が到着した時点を要求時刻とし、キュー待ち、前の再生との重なり、再生間隔とアンダーランを記録 |
| 連続試験 | ストリームの継続時間、完了発話数、プロセスPSSとAndroidの熱状態を記録 |
| ASR | 中断要求、音声停止処理後の時刻、認識開始・準備・発話開始・最終結果・再生要求、試験音声の固有フレーズ検出を記録 |

短文ウォーム中央値 約500 ms、RTF 1未満を判定基準にする。p95も同じJSONから確認する。会話の再生待ちは発話順を守るための待ち時間を含む。再生ヘッドの初回観測はマイクで測った音の到達時刻とは異なる。音質の主観評価とASRの漏れなし判定は実機で行う。受入前はPixel性能・10分安定性・20人の聞き分けを未判定とする。

## 実装・再現

- Native ONNX Runtime Android 1.22.0（MIT）。同じ条件ではセッションを常駐させる。XNNPACKは未対応演算にCPUを使用する。EPのノード割当・高速化は未判定。q4は比較対象から外した。
- モデル・声ベクトル・トークナイザは [ONNX Communityの固定リビジョン](https://huggingface.co/onnx-community/Kokoro-82M-v1.0-ONNX/tree/1939ad2a8e416c0acfeecc08a694d14ef25f2231)（Apache-2.0）。P3.6の `realtime/prepare.py` から取得するSHA-256をAPKに同梱。ダウンロードしたファイルは検証後に原子的に配置する。
- 20人の声設定はP3.5の `profiles.json` を直接使用。事前生成クリップのモデル・声・アクセント・話速・MP3ハッシュをビルド時に照合する。P4.2の音声は、この公開ラボに持ち込まず、同じ公開プロファイルの来歴で照合を受ける。
- eSpeak NG 1.52.0の [対応ソースとライセンス](https://github.com/espeak-ng/espeak-ng/tree/4870adfa25b1a32b4361592f1be8a40337c58d6c)（GPL-3.0-or-later）。JNIラッパーもGPL-3.0-or-later。データは同リビジョン由来の `espeakng-loader==0.2.4` から取り出してハッシュを記録する。P3.5のPython phonemizerと句読点・略語の処理差があるため、比較BとCを分け、音素をログに保持する。
- ビルドに必要なものはJDK 21、Python 3.12、Android SDK 36、Build Tools 36.0.0、NDK 28.2.13676358、CMake 3.22.1。リポジトリのルートから以下を実行する。

```bash
python3 -m pip install 'espeakng-loader==0.2.4'
./android/gradlew -p experiments/character-voice-lab/android-native :app:assembleDebug --no-daemon
```
