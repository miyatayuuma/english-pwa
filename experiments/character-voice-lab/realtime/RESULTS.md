# P3.6 デスクトップ実測

Pixel 9受入は未実施。以下はLinux x86-64のChromium 140とONNX Runtime 1.32.0 CPUでの実測。ブラウザは幅412 pxのタッチ条件、スレッド分離あり、論理CPU 9。Kokoro-82M v1.0、Jenniferの `I found it.` を、同一セッションで1回合成してから5回測定した。モデルはローカル配信。RTFの分母は両端の長い無音を整えたPCMの長さ。

## 初音声とRTF

| 方式 | 初期化 | 合成要求→再生開始 p50 / p95 | RTF p50 |
| --- | ---: | ---: | ---: |
| WASM q8 1スレッド | 2,860 ms | 3,765 / 4,094 ms | 4.172 |
| WASM q8 2スレッド | 2,226 ms | 2,897 / 2,950 ms | 3.192 |
| WASM q8 4スレッド | 1,919 ms | 2,627 / 2,655 ms | 2.893 |
| WASM q8 8スレッド | 3,359 ms | 2,836 / 3,261 ms | 3.122 |
| WASM q4 4スレッド | 5,482 ms | 1,747 / 1,777 ms | 1.857 |
| WASM FP32 4スレッド | 2,912 ms | 1,394 / 1,509 ms | 1.511 |
| WebGPU FP32、ソフトウェアGPU | 2,924 ms | 初回合成が60秒でタイムアウト | — |

この環境ではWASM q8は4スレッドが最速。WASM全体ではFP32が最速だった。q8重み92.4 MB、q4重み305.2 MB、FP32重み325.5 MB。この配布版のq4はq8より大きい。実機受入の初回はq8を使い、同じ試行でFP32と比較する。WebGPUの失敗はソフトウェアGPU構成での結果。

| デスクトップネイティブCPU・4スレッド | 初期化 | 合成 p50 | RTF p50 | ピークRSS |
| --- | ---: | ---: | ---: | ---: |
| q8 | 715 ms | 725 ms | 0.815 | 325 MiB |
| q4 | 625 ms | 622 ms | 0.683 | 570 MiB |
| FP32 | 960 ms | 619 ms | 0.696 | 569 MiB |

CPU版の時間はPCM生成まで。再生は計測対象外。q8の別ラウンドでは1／2／8スレッドの合成p50が950／706／639 ms、RTF p50が1.068／0.793／0.718だった。計測プロセスはランタイムのテレメトリを無効にし、ソケットをOS側で遮断した。AndroidのARM64 CPU・XNNPACK・アクセラレーターはこの計測に含まれない。

## 会話・割り込み・メモリ

- q8／4スレッドの4ターン会話で7発話を順番に再生し、6回は前の発話の再生と次の合成が重なった。発話間の無音はp50 5.21秒、p95 12.75秒。合成の先読みを使っても、この構成では自然な会話速度の目標に届かなかった。
- 合成中と再生中に割り込み、後続音声の再生を停止した。Chromiumの模擬マイク入力で声による停止と発話検出を通過。ブラウザASRのイベントを模擬した試験では、割り込み→ASR開始→最終結果→終了の順序と認識中の再生開始抑止を確認した。Pixel実機のマイク・スピーカーとASRは未検証。
- q8／4スレッドの連続運転は10分7秒で112発話をすべて再生し、エラー・中断なし。96回は前の発話と次の合成が重なった。連続試験のRTF p50は2.320、発話間無音のp95は7.32秒。
- モデルを保存後、ローカルサーバーを停止し、Chromiumをオフラインにして新規ページを開いた。q8のモデル再初期化と短文5回の合成・再生が完了した。
- Linuxの `smaps_rollup` でChromium全プロセスのPSSを合計した別試行では、モデル準備前114 MiB、q8準備後543 MiB、FP32準備後1,270 MiB。後者はq8を解放した同一ブラウザで測定した。PixelのPSS・温度・電力は未測定。

## 音質と発音の比較

- 20人の公開音声プロフィールを読み込み、同じ重みのリビジョン、声ID、アクセント、話速を照合した。共通設定に切り替えた事前生成スクリプトでP3.5の既存95本がすべてそのまま再利用された。
- ネイティブCPU版で米音2人・英音1人の自作英文11条件を比較。Voskの英語小型モデルで、大文字・句読点を除いた書き起こしはFP32とq4で11/11一致、q8で10/11一致。q8の差は `upstairs` の `up stairs` への分割だった。
- 3種類とも波形のクリップは0サンプル。FP32に対する再生長の最大差はq8で70 ms、q4で130 ms。レベル差は同じ条件で最大0.25 dBだった。発音指定版の `read` は同じ音素列を入力して合成まで確認した。音素列や自動書き起こしから耳で感じる声質・韻律の一致や、同綴異音語の聞き分けまで確定できないため、試聴ページで確認する。

再生開始約500 ms・RTF 1未満を同時に確認できたブラウザ構成はなかった。P6ではPixelでq8／FP32を実測し、遅延が残る場合はAndroidネイティブで同じ声を測る。固定の導入音声を事前生成して次の文を並行合成する方法は、ネイティブ受入中も同じ人物の声を維持できる。
